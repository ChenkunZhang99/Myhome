# 003 · 登录设备与会话轮换

- 状态：完成，待独立复核
- 日期：2026-08-24
- 目标：改密码后旧会话必须失效；用户能查看并撤销仍有效的登录设备。

## 1. 范围

本步骤完成：

- 保存浏览器 User-Agent、会话创建时间和最近使用时间。
- 在设置中列出最多 50 个有效设备会话并标记当前设备。
- 支持撤销单个设备、退出其他设备、退出所有设备。
- 修改或取消密码时，旧设备和未使用的邮箱登录令牌全部失效；当前浏览器收到全新的会话 Cookie，保持登录。
- 最近使用时间最多每 15 分钟写一次，避免每个库存请求都产生额外 D1 写入。
- 隐私说明同步披露新增的设备信息。

本步骤不处理项目所有者明确暂缓的密码哈希强度、登录限流、账号锁定拒绝服务、邮箱验证和 Resend 配置。

## 2. 数据结构

`sessions` 新增：

| 字段           | 用途                                                           |
| -------------- | -------------------------------------------------------------- |
| `session_id`   | 可公开给当前账号用于撤销的随机标识；真正的 token hash 不出库。 |
| `user_agent`   | 用于显示大致浏览器和设备，不保存 IP。最长 300 字符。           |
| `last_seen_at` | 最近一次活跃时间，15 分钟节流更新。                            |

老数据库通过 `ADDED_COLUMNS` 补列：

- 旧会话使用 SQLite `randomblob(16)` 回填随机 `session_id`。
- `last_seen_at` 由原 `created_at` 回填。
- 补列完成后才创建 `session_id` 唯一索引，避免重演“索引先于列”的初始化错误。

## 3. API 与安全行为

新增 `/api/sessions`：

- `GET`：只返回当前账号自己的有效设备会话，不返回一次性邮箱登录令牌。
- `POST revoke`：`user_id + session_id` 双条件撤销，不能用已知 ID 撤销别人的设备。
- `POST revokeOthers`：保留当前 token，撤销同账号其他设备。
- `POST revokeAll`：撤销设备会话和待使用登录链接，并清除当前 Cookie。

改密码使用一个 D1 batch 同时执行：

1. 写入新密码哈希并清登录失败计数。
2. 删除该账号所有旧会话和一次性登录令牌。
3. 为当前浏览器写入全新的设备会话。

三步在同一事务中提交，避免出现“密码已经改了，但删除旧会话失败”的半完成状态。

## 4. 界面

账号设置新增“登录设备”：

- 根据 User-Agent 显示 Edge、Chrome、Firefox、Safari 和 Windows、Mac、iPhone、iPad、Android 的粗略组合。
- 不认识的 User-Agent 显示“未知设备”，不把原始长字符串直接塞进主界面。
- 每行显示最近使用时间；非当前设备有独立退出按钮。
- 提供“退出其他设备”和“退出所有设备”。

修改或取消密码后的提示明确说明其他设备已经退出。

会话 HTTP 场景实际断言：

1. 同一账号两个浏览器登录后，设备列表返回两项且只有一项标为当前。
2. 撤销指定设备后，该 Cookie 的 `/api/auth` 校验立即变为无效。
3. 修改密码后，修改前的当前 Cookie 和另一设备 Cookie 都失效。
4. 修改密码响应签发新 Cookie，新 Cookie 有效，列表只剩一个当前设备。
5. 新密码可以登录；“退出其他设备”只保留当前设备。
6. “退出所有设备”清 Cookie，并让当前与其他设备全部失效。

## 6. 隐私与边界

- 数据库只保存随机 token 的 SHA-256 哈希，明文会话 token 仍只存在于 HttpOnly Cookie。
- API 返回随机 `session_id`，不返回 `token_hash`。
- 不记录 IP、精确位置、设备指纹或浏览历史。
- User-Agent 可以伪造，只用于帮助用户辨认，不作为安全认证依据。
- 所有管理动作先由当前有效会话确定账号，再按该 `user_id` 限定 SQL。

## 7. 已知不足

- 旧 schema 的补列逻辑由源码和新库路径验证，尚未在生产库副本上做一次完整迁移演练；部署前应先备份 D1。
- 设备名称来自 User-Agent，浏览器收紧 UA 后可能只能显示“未知设备”。
- 最多列出 50 个设备；“退出所有设备”仍会撤销未显示的更多会话。
- 当前没有为设备自定义名称的功能。
- 没有登录通知或异地登录告警；项目也没有邮件服务。

## 8. 给下一位审计者的检查清单

1. 在一份旧结构 D1 副本上部署，确认旧会话全部获得唯一 `session_id`。
2. 并发执行两次改密码，确认只有最后一次事务签发的会话仍符合产品预期。
3. 手工构造别人的 `session_id` 调用 revoke，确认返回 404 且对方会话不变。
4. 检查修改密码响应的 `Set-Cookie`，确认仍有 `HttpOnly; SameSite=Lax; Secure`。
5. 在手机 Safari 和桌面浏览器打开设置，检查设备列表的窄屏换行和按钮可点区域。
