# 005 · 首次使用引导与反馈入口

- 状态：完成，待独立复核
- 日期：2026-08-24
- 目标：让第一次进入空家庭的人知道从哪里开始，也让使用中的问题有明确去处。

## 1. 范围

本步骤完成：

- 只有库存接口成功返回、且当前家庭确实没有真实物品时，才把它识别为新家庭。
- 第一次进入新家庭时自动打开三步引导。
- 引导可以关闭，并按家庭 ID 记在当前浏览器；示例横幅始终保留“查看新手指南”，可以再次打开。
- 引导直接连接手动添加、小票识别、Flyer 门店区和家庭设置，不做只能读不能操作的介绍页。
- 侧边栏新增“反馈与建议”，设置面板新增“报告问题”和“提出建议”。
- GitHub 增加两份结构化 Issue Form，并在界面和模板中重复提醒：反馈公开，不要提交家庭隐私或 API 密钥。
- 修复侧边栏“家庭设置”原来错误滚动到预算区的问题，现在会真正打开设置。

## 2. 新家庭判断

原来的 `showingDemo` 同时覆盖两种完全不同的状态：

1. 库存接口成功，但当前家庭是空的；
2. 库存接口失败，页面回退到示例数据。

如果只看 `items.length === 0`，断网或服务错误时也会弹出“欢迎新用户”，造成误导。现在增加 `inventoryReady`：只有成功读完 `/api/inventory` 才设为 true，`newHousehold` 必须同时满足：

```text
示例正在显示 + 库存接口确实成功
```

家庭资料读取失败不会挡住主页面，也不会把失败状态写成“已看过引导”。

## 3. 引导流程

三步都是可立即执行的动作：

1. **录入真实库存**：手动添加，或者上传小票。
2. **收藏常去门店**：平滑定位到现有 Flyer 门店设置区。
3. **按需补全家庭设置**：邀请家人、语言和 AI 都明确说明不是开始记库存的前置条件。

关闭记录使用 `hsp.onboarding.{householdId}`，因此：

- 同一浏览器里，不同家庭互不影响；
- 关闭后不会每次刷新都弹出；
- 换一台设备会再出现一次，这是有意的，因为引导状态不值得增加服务端表和同步成本；
- 示例横幅的“查看新手指南”不受关闭记录限制。

加入第一件真实物品后，示例和引导入口一起退出，不会混进真实库存。

## 4. 反馈流程

反馈落到公开 GitHub Issues：

- 仓库匿名访问返回 200，确认是公开仓库。
- Issues 新建入口有效；未登录 GitHub 时可能先要求登录。
- Bug 表要求描述现象、重现步骤、设备和浏览器。
- 建议表要求先写使用场景、现有做法和希望结果，避免只收到一句抽象的“加某功能”。
- 两份表都有必选隐私确认，不要求也不主动收集邮箱。

应用中有三个入口：侧边栏、设置面板、首次引导底部。外链都使用新标签页和 `rel="noreferrer"`。

## 5. 隐私取舍

GitHub Issue 是公开内容，所以不能把当前页面状态、库存、浏览器信息或账号信息自动附加上去。本步骤没有做“自动截屏”“自动上传日志”或“自动带上家庭 ID”。

界面和表单都明确要求删除或遮住：

- 姓名与邮箱；
- 小票和库存照片；
- 家庭成员信息；
- OpenAI API 密钥；
- 其他能识别家庭的信息。

## 7. 已知边界

- 反馈依赖 GitHub 账号；没有 GitHub 的普通家庭成员不能直接提交。这比建立一套无人查看的数据库反馈表更诚实，但不是最终的非技术用户体验。
- 引导关闭状态只保存在当前浏览器，不跨设备同步。
- 引导不会判断门店、预算或 AI 是否已经配置，只负责首次入口，不做完整进度追踪。
- 这是使用流程引导，不是互动教学；不会替用户创建示例以外的真实数据。
- GitHub 模板本身无法阻止用户主动粘贴隐私，只能通过显眼说明和必选确认降低风险。

## 8. 给下一位审计者的检查清单

1. 新注册空账号，确认引导自动出现且三个动作都到达正确位置。
2. 关闭后刷新，确认不再自动弹；点示例横幅可重新打开。
3. 新建第二个空家庭，确认第一家的关闭记录不会压掉第二家的引导。
4. 模拟 `/api/inventory` 失败，确认不会误显示“这是一个新家庭”。
5. 在窄屏检查步骤卡、双按钮和反馈链接的换行。
6. 推送模板后点两个反馈入口，确认 GitHub 选择了正确的 Issue Form。
