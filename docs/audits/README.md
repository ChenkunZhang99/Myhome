# 变更审计记录

这个目录给接手项目的人和其他 AI 审计者使用。每完成一个可以独立验证的修改单元，就新增一份编号文档，不覆盖旧记录。

## 命名

`NNN-short-topic.md`，例如 `001-integration-test-foundation.md`。

## 每份记录必须包含

1. 范围：这一步解决什么，不解决什么。
2. 改动：涉及的文件和关键设计选择。
3. 验证：可复制的命令、实际结果和覆盖到的行为。
4. 安全边界：是否触碰生产数据、密钥或外部服务。
5. 已知不足：本步骤之后仍然存在的风险。
6. 审计建议：下一位审计者应该重点质疑什么。

## 状态约定

- `完成`：实现和验证都通过。
- `待复核`：实现已完成，但需要独立审计。
- `阻塞`：无法在当前环境完成，并写明原因。

这些文档是证据索引，不代替 Git diff、自动化测试或代码审查。文档中的结论应能通过所列命令重新得到。
